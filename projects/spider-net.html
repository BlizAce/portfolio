🕸 Spider Net

A web routing engine that directs you to relevant sites without hoarding the full text of the internet. Brutalist efficiency: block-compressed inverted index, hierarchical semantic routing, local LLM re-ranking.

PythonFlask APIDockerllama.cppzstd blocks

Crawl like it costs something

Naive breadth-first crawling burns bandwidth on noise. Spider Net scores before it fetches:

  • Interest-scored scheduler — URLs prioritised by past query signals and page scores, not link order.
  • Bounded N-degree spider with semantic link filtering, sitemap/RSS discovery and robots.txt compliance.
  • Proxy rotation for large-scale scraping without burning the home IP.
  • Atomic memory guarantees — crawler state and search index never diverge under failure.

Store like it costs something

The index keeps pointers, not paragraphs. Data blocks are compressed (.tar.zst) and lazy-loaded into RAM only when a query touches them; hierarchical tree junctions prune the candidate space before anything decompresses.

Design rule: a search engine that needs the whole internet's text has already lost. Route, score, re-rank — fetch only what the user opens.

The query path, in order: keyword hash lookup locates candidate blocks, tree junctions prune the space hierarchically, only surviving blocks decompress into RAM, candidates get scored — and optionally handed to the reranker.

  • GET /search?q=… · POST /search {"q":"…","top_n":10}
  • GET /suggest?q=… for type-ahead, /stats and /health for ops.
  • Atomic memory guarantees: index and crawler state never diverge under failure.

A deliberately plain search UI — zero frameworks, instant load, keyboard-first. Auto-suggestions come straight from the keyword hash, not a server round-trip to some other company.

The live instance runs on the home LAN; this portfolio is its only public window.

Drive the bounded spider programmatically:

  • POST /crawl/start {"seed_urls":[…]} — N-degree crawl with semantic link filtering, sitemap/RSS discovery and robots.txt compliance.
  • /crawl/status, POST /crawl/stop, POST /crawl/flush for graceful shutdowns, /crawl/docs to inspect what landed.
  • The scheduler prioritises URLs by past query signals and page scores — crawl budget follows interest, not link order.

Real-time view of everything: index size, block counts, crawl progress, queue depth, system health. Built for the wall-mounted terminal scenario — glanceable at a metre's distance.

POST /rerank takes the lexical top candidates and re-scores them semantically with a local 3B model under llama.cpp (/status, /health for ops).

  • Reranking happens on a narrowed candidate set — GPU seconds are spent only where they change rankings.
  • Fully optional: disable it in config and the engine degrades gracefully to pure lexical search.

A chat interface over the whole system: answers grounded in Spider Net's own index plus the scraped corpus, with multi-conversation support. RAG done locally — the retrieval, the generation and the conversation history all stay on the machine you point at.

One-click ops

./scripts/start.sh start builds and health-checks the container; a systemd watchdog keeps it alive across boots and reboots.

🧠

Semantic where it counts

Embedding-based relevance scoring on candidates the lexical index already narrowed — precision without paying GPU prices at query time.

🔒

Yours, entirely

No cloud dependency, no query logging by strangers. The whole stack runs on a machine you can point at.

Every operation is one command with a sane default:

  • start / stop / restart / logs / shell / status — build, run, debug and inspect without opening the compose file.
  • start_auto.sh install registers a user-level systemd service that auto-starts on boot and health-checks every 30 seconds.
  • All persistent data lives in one mounted directory: blocks, index, models, logs, document cache.

The design goal: a machine you forget about until you want to search something.

Two-stage retrieval done economically:

  • Stage one is lexical and nearly free — keyword hash plus hierarchical tree junctions prune millions of candidates down to dozens.
  • Stage two spends model compute only on that handful: embedding relevance scoring, then optional 3B-LLM re-ranking for ordering nuance.
  • Query latency stays in the tens of milliseconds; reranking is a config flag away from being swapped for any local GGUF model.

The philosophical core of the project: routing beats hoarding, and owning beats renting.

  • No third party sees your queries — there is no third party.
  • The index stores pointers and scores, not paragraphs, so it stays small enough to own outright.
  • Built for the scenario where internet access is intermittent, expensive, or simply not something you trust with your search history.
